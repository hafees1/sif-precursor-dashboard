# SIF Precursor Detection Engine — SIH 2026, PS 26165

AI/NLP prototype for Oil India Limited that classifies UA/UC, near-miss and incident
reports as SIF-potential vs non-SIF-potential, tags each to the relevant IOGP
Life-Saving Rule, and surfaces recurring precursor patterns via an interactive dashboard.

## Files

| File | Purpose |
|---|---|
| `sif_precursor_engine.ipynb` | Main notebook: EDA, rule-based engine, ML classifier, hybrid model, LSR tagger, precursor mining, model export |
| `dashboard_app.py` | Streamlit dashboard consuming the notebook's exported artifacts |
| `oil_synthetic_dataset.csv` | Synthetic dataset used to build/validate the prototype (5,000 reports) |
| `requirements.txt` | Python dependencies |
| `artifacts/` | Generated by the notebook — processed data, ranking tables, trained models |

## Setup

```bash
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Run

1. **Run the notebook first** (generates everything the dashboard needs):
   ```bash
   jupyter notebook sif_precursor_engine.ipynb
   ```
   Run all cells top to bottom. This creates the `artifacts/` folder.

2. **Launch the dashboard:**
   ```bash
   streamlit run dashboard_app.py
   ```
   Opens at http://localhost:8501

## Using real OIL data instead of the synthetic dataset

The pipeline only strictly requires a `report_text` column. To use it on a real
HSSE export:

1. Point `DATA_PATH` in the notebook at your file.
2. If you don't have `sif_potential` / `life_saving_rule` ground-truth labels yet,
   the rule-based engine (Section 3) and keyword LSR tagger (Section 6) still work
   with **zero labelled data** — they're pure domain-knowledge lexicons.
3. To train the ML/hybrid layers, get ~300–500 reports human-triaged (OIL's existing
   monthly/quarterly manual review is a ready-made source) and use those as labels.
4. Validate `LSR_MAP` and the hazard lexicons in Section 3/6 against OIL's actual
   HSSE taxonomy — the current mapping is a reasonable starting guess, not gospel.

## Known limitations (read before demoing)

- The synthetic dataset is generated from sentence templates, so the ML model hits
  near-perfect scores on it — that reflects the templated data, not real-world
  performance. Section 5.1 of the notebook stress-tests the pipeline on hand-written,
  non-templated sentences for a more honest read (~50-80% depending on phrasing).
- The rule-engine's severity-language lexicon is inherently limited to phrases it
  recognises; expanding it against real report language is expected, ongoing work.
- Add a human review/correction loop in the dashboard for a real pilot, feeding
  corrections back into retraining (active learning).
